## 本人と決めたこと
- 主な使い道は **Claude Code への直接入力**（Claude デスクトップアプリとターミナルの `claude`）。
  ここにはクリックできるファイルツリーが無いので、**最小の候補画面は作る**（本人も了承）。
- 声は**止めない**。候補画面が開いている間に喋った分も文に入れる。
- 画面は**ピルの上に候補の列が数行伸びるだけ**（プレビュー窓は作らない）。
  選び方は**日本語入力の変換候補と同じ**: 数字キー 1〜9 でワンタッチ決定、Tab で次の候補群。上下キー移動は使わない。
- 入れる形の既定は **`@リポジトリ直下からの相対パス`**。設定で絶対パスなどに変えられる。
- リポジトリは**自動＋手動**（自動で拾い、設定で追加・除外）。
- 探し方は**ファイル名のあいまい検索＋ベクトル検索の両方**。ベクトル化は **Gemini Embedding 2**、
  本人が指定した範囲のファイルは全部ベクトル化する。「できるだけ機能を付けて」。
- 録音していないときは**別のキーで開ける**（選んだパスをその場に貼る。打鍵中にも使える）。
- 補助として VS Code / Cursor 拡張と Finder にも対応する（本人「対応するなら別にいい」）。録音中に**開いたファイルは全部入れる**。

## 動き
1. 録音中（ダブルタップ待ちを含む）に @ を打つ → 前面アプリへは届けずに消費し、候補画面を開く。
   その時点を「差し込み位置」として記録（スクショの `[画像N]` と同じ仕組み）。hold 録音はハンズフリーに切り替える。
   - 判定は**打たれた文字が「@」か**で見る（US 配列は ⇧2、JIS 配列は専用キー。キーコードで決め打ちしない）。
   - 消費するには active なイベントタップが要る。**録音中だけ** active タップを張り、録音が終わったら外す
     （今の `HotkeyMonitor` は listen-only のまま。常時 active にすると全打鍵の経路に乗るため）。
2. 開いた瞬間の候補: 対象リポジトリの**変更中のファイル**（staged → changes → 未追跡の順、`git status --porcelain`）。
3. 打った文字と、開いてから喋った声で候補を絞る（声は同時に文にも入る）。並びはあいまい検索とベクトル検索の点数を混ぜ、
   よく選ぶ・最近選んだものを上げる。候補に**クリップボードの中身**（パスや URL のとき）も混ぜる。
4. 決め方: 1〜9 でその候補、Enter で 1 番目、Tab / ⇧Tab で次・前の 9 件、Esc で閉じる（何も入れない）。
   候補名の後ろに `#L10-20` と打てば行範囲付きで入る。
5. 決めたら画面を閉じ、記録した位置に `@パス` を入れる。録音はそのまま続く（遅延ゼロ。録音・認識の経路には触らない）。
   1 回の録音で何回でも開ける。ピルに入れたパスの数をバッジで出す。
6. 確定時、整形・翻訳の前に `@パス` を印として埋めて通し、消えたり書き換わったりしていたら相対位置で置き直す
   （整形の LLM がパスを直さないように、印は確定文の該当位置へ後から差し戻す）。
7. 録音していないとき: 別のキー（既定 ⌥@ 案）で同じ画面を開き、決めたら `@パス` をそのまま貼る。

## 候補画面
- 置き場所: ピルの真上に伸びる NSPanel（`.nonactivatingPanel`・`canBecomeKey`）。前面アプリはアクティブのまま
  キー入力だけ受ける（先例 `UI/SideNotch.swift`）。マウスカーソルは動かさない。
- 1 行 = 番号・ファイル名・薄い字でフォルダ・状態印（M / A / ?）。9 行まで。見た目は字幕・ピルと同じガラス。
- プレビュー（中身の確認）は本人が「列だけ」を選んだので**入れない**。要望が出たら Space で開く形を後から足す。

## 対象リポジトリの決め方
- 自動: `~/Project` 以下の git リポジトリ（深さ 2 まで、`_archive` と worktree の重複は除く）。設定で追加・除外。
- 最初に出すリポジトリ:
  - ターミナルの `claude`: 前面のターミナルで動いているプロセスの作業フォルダ（`proc_pidinfo` の cwd）。
  - Claude デスクトップ: 今のセッションのフォルダが読めればそれ（読み方は実装前に調べる。【推測】アプリの状態ファイルにある）、
    読めなければ最後に選んだリポジトリ。
  - それ以外のアプリ: 最後に選んだリポジトリ。画面の上でリポジトリ名を出し、⌘1〜9 等で切り替えられるようにする。

## ベクトル検索（Gemini Embedding 2）
- 鍵は既存の `GEMINI_API_KEY`（設定 › API キー → 環境変数 → 中央 Keychain の順）。無ければあいまい検索だけで動く。
- 対象: 設定で選んだリポジトリのテキストファイル。`.gitignore` 対象・`.env*`・鍵（`*.pem` `*.key` 等）・
  バイナリ・大きすぎるファイルは**送らない**。ファイルを数百行ごとに切ってベクトル化。
- 保存: `~/Library/Application Support/voicekey/file-index/` の SQLite（ファイルのハッシュで変更分だけ作り直す）。
  作り直しは録音していないときに裏で、FSEvents で変更を拾う。
- 検索時は問い合わせ文 1 回だけをベクトル化（声・打鍵が止まって 0.3 秒後。連打で投げない）。
- 費用: 【推測】voicekey 1 本の初回で約 $0.3〜0.5、`~/Project` 全体で数ドル（単価は第三者の集計で約 $0.20/100 万トークン、
  公式価格は実装前に確かめる）。**初回のベクトル化は件数と金額を出して本人の承認を取ってから**始める。問い合わせは 1 回 $0.0001 未満。
- API 料金表示（`ApiPricing.swift`）に Gemini Embedding の行を足す。

## 補助: VS Code / Cursor 拡張と Finder（優先度低・最後）
- 拡張: `onDidChangeActiveTextEditor` で開いたファイルと選択行を取り、ローカル通信（Unix ソケット）で voicekey へ送る。
  録音中に開いたファイルは全部、その時点の位置に `@パス`（選択があれば `#L`）で入る。
- Finder: 録音中に選択が変わったらアクセシビリティで選択中のファイルを読む（クリックの合成はしない）。
- ピルにチップを並べ、削除キーで最後の 1 つを取り消せる。貼り先は録音を始めたアプリに固定し、貼る直前にそのアプリへ戻す。
